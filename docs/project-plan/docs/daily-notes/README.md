# CoreBankX QA Lab — Daily Development Notes

This directory contains the day-by-day development journal of the CoreBankX QA Lab project.

The purpose of these notes is to record exactly how the project was created, developed, tested and enhanced.

---

## Daily Documentation

Each project workday will have a separate Markdown document.

Example:

- Day-01.md
- Day-02.md
- Day-03.md
- Day-04.md
- Day-05.md

---

## Information Recorded Each Day

Each daily note will contain:

### 1. Date
The actual date of development.

### 2. Day
Project day number.

### 3. Objectives
What we planned to accomplish.

### 4. Activities Performed
Detailed step-by-step activities completed.

### 5. Files Created
New files created during the day.

### 6. Files Modified
Existing files changed during the day.

### 7. Code Changes
Important code written or modified.

### 8. Commands Used
Git, terminal and other commands used.

### 9. Configuration
Environment and application configuration changes.

### 10. Testing
Testing performed and results.

### 11. Issues
Problems or errors encountered.

### 12. Solutions
How each problem was resolved.

### 13. Git/GitHub Activity
Commits, branches and repository changes.

### 14. Technologies Used
Technologies and tools used during the day.

### 15. Concepts Learned
Important technical and QA concepts learned.

### 16. Interview Questions
Interview questions related to the day's work.

### 17. Next Steps
Activities planned for the next development session.

---

## Daily Excel Journal

A detailed Excel project journal will also be maintained.

The Excel journal will contain:

- Day
- Date
- Time spent
- Objective
- Activity
- Step
- Technology
- File/Folder
- Code Change
- Command
- Configuration
- Testing
- Issue
- Solution
- Git Commit
- Concept Learned
- Interview Question
- Status
- Next Step

---

## Documentation Rule

The daily documentation will reflect the actual work performed.

No steps will be recorded as completed unless they were actually performed.

The Markdown notes and Excel journal will be synchronized at the end of each development day.

---

## Project Documentation Principle

> Build it → Test it → Document it → Commit it → Learn it → Add it to the Interview Bank
